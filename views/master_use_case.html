Discovery

How to Use This Library

Before committing budget or changing production systems, teams need clear answers to practical engineering questions:

Which architecture to choose?
How will migration happen?
What risks exist?
How do we maintain compliance?
What downtime to expect?
Which assumptions need validation?

These are reference architectures, not client case studies. A delivery case study is published separately only when the scope, evidence, and client disclosure approval are available.

What Each Reference Covers

What You Can Evaluate

Problem Pattern

The operational or technical condition the architecture is intended to address, with the questions that should be answered before implementation.

Inputs to Assess

The environment details that change the final design: dependencies, capacity, risk tolerance, recovery objectives, and current controls.

Target Architecture

The major services, data flows, compute, storage, network, and security layers that make up the pattern.

Delivery Considerations

Sequencing, validation points, cutover planning, and rollback requirements that a project team should define.

Governance Requirements

Identity, access, monitoring, cost ownership, and audit controls that the target platform must support.

Operating Model

The runbooks, service ownership, monitoring, capacity management, and optimisation work needed after launch.
